# Application update releases

Boundary Vision uses `electron-updater` with the electron-builder GitHub Releases provider and the Windows x64 NSIS target. The public `SamirShaikh05/Boundary-Vision` repository currently has a `models-v1` release for model assets; that model-only release does not configure or test application updates. `electron-builder.config.cjs` reads `BOUNDARY_VISION_GITHUB_OWNER` and `BOUNDARY_VISION_GITHUB_REPO`; it rejects a partial/invalid pair and configures a draft application release when both are supplied. electron-builder embeds the update feed as `resources/app-update.yml` and creates `latest.yml` plus the NSIS installer and blockmap assets. No token or repository URL is hard-coded.

The app checks 3.5 seconds after startup, every six hours, and from **Settings & About → Check for updates**, only when packaged with feed metadata. Development builds report that updates are disabled. Updates are never downloaded automatically: the user selects Download, then Restart and install; Later leaves a completed download ready. A sidebar marker and banner show confirmed updates and release notes. The updater does not install on ordinary app quit. The main process rejects a restart while inference or a model update is active. Offline or missing-release errors are shown with a retry action. electron-updater checks the release version and platform/architecture; Windows update signature validation depends on using the same trusted signing identity for the installed app and its updates.

## Build and publish a Windows release

1. Use the intended **public** GitHub repository for application releases and configure publishing access. The model-only `models-v1` release is not an application update release. Do not ship a GitHub token in the app; a private app-release repository would require end-user credentials.
2. Update the app version in `frontend/package.json` and `frontend/package-lock.json`; use a strictly increasing release version. Update app/model compatibility or release notes as appropriate. Run `npm ci` and `npm run build` first.
3. Configure the real owner and repository in the release shell, plus a narrowly scoped `GH_TOKEN` that can create/upload releases. Configure the Windows signing certificate using electron-builder's supported secure environment variables (for example `CSC_LINK` or `WIN_CSC_LINK` and, if needed, `CSC_KEY_PASSWORD`). Do not place token or private-key material in source, checked-in config, or logs.
4. On the Windows x64 release machine, prepare the required Python environment and run `npm run release:win`. FFmpeg/FFprobe are not needed to build or publish the installer and are not included.
5. Verify the draft's installer, `.blockmap`, and `latest.yml`; verify Authenticode signatures on the installer, Electron app, and worker; verify the generated `resources/app-update.yml` points to the intended repository; install this exact signed build and test update check/download/restart against a later test release. Publish the draft only after those checks, then verify the public assets and update again from a clean install.
6. Publish a signed update-enabled bootstrap installer manually for users on any older build that lacks `app-update.yml`. Such an existing installation cannot discover the GitHub feed until it is replaced with an update-enabled build.

The current app version is `0.1.0`. The public release list currently contains the model-only `models-v1` release and no application update release. A local `package:win` build without the publisher configuration has no `resources/app-update.yml`, so its updater reports that application updates are not configured. `release:win` needs the owner/repository, publishing token, and signing values supplied securely at release time. Live application update checking, downloading, signature validation on a real signing certificate, and restart/install have not been exercised against a published app release. FFmpeg/FFprobe are optional user-installed tools and are not part of installer release requirements.

See the official [electron-builder auto-update guide](https://www.electron.build/v26/docs/features/auto-update/), [GitHub publishing guide](https://www.electron.build/v26/docs/publish/), and [electron-updater API](https://www.electron.build/v26/docs/api/electron-updater.class.appupdater/).
