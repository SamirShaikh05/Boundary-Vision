# Windows release requirements

> **Release status:** The current installer is not ready for public distribution. Model assets are published, but packaged model download/inference is not end-to-end verified. No application update release/feed is configured or tested, distributed binaries are unsigned, and clean-machine validation remains outstanding.

## Packaged runtime

The Windows installer includes the PyInstaller `boundary-worker.exe` one-folder payload, including its Python runtime and pinned inference dependencies. Packaged inference launches that executable directly and does not require system Python. The packaging script builds it using the exact Python version in `.python-version` from `backend/.venv`; this is a reproducible build constraint, not a Python requirement for packaged users. Development mode continues to use `backend/.venv` to run `worker_entry.py`. The repository clone and installer build do not require model weight files: before packaging, the script clears only `frontend/build-resources/models`, stages the sanitized registry, and validates that `registry.json` is the sole entry. Electron Builder copies that exact file rather than the directory, preventing stale weights or other artifacts from entering the installer. The script does not download or bundle `.pt` files. If a local checkpoint is present in repository `models/`, it verifies its size and SHA-256 against the registry; otherwise it builds without it.

Release builds still need real verification for end-to-end inference, hosted model installation, signing, and user-machine installation. The YOLO26n and YOLO26l checkpoints are published in the public [`models-v1` GitHub Release](https://github.com/SamirShaikh05/Boundary-Vision/releases/tag/models-v1); their release sizes and SHA-256 digests match the registry. This is not evidence that the packaged app has downloaded, loaded, or inferred with them. FFmpeg and FFprobe are not included in the installer and are not required at startup or for image inference. When a user requests video processing, Boundary Vision offers to download the pinned FFmpeg 9.0.2 Essentials ZIP from Gyan.dev, verifies its SHA-256, extracts only the two expected executables, checks that both run, and stores them under per-user `userData/tools/ffmpeg/9.0.2` for reuse across app updates. Models are not bundled. Versioned checkpoints live under `userData/models/{model-id}/{model-version}/{filename}`; settings including the selected model version remain under `userData` across application updates.

Contributors who need source-checkout inference can download the needed asset from `models-v1` into `models/` using the checkpoint filename in the registry, then verify the expected file size and SHA-256. For packaged-app inference, install the model through Model Manager instead. Model downloads are separate from application publishing: `npm run package:win` builds locally without publishing, and the `release:win` script publishes the Windows application artifacts when explicitly configured; neither script uploads model files.

This packaging approach was inspected and the worker capability handshake was exercised from the final unpacked layout on the build machine. Full inference from the installed layout and a clean-machine test remain outstanding. The PyInstaller log reports missing `lap`, an optional Ultralytics tracking dependency; this product does not use object tracking. The shipped runtime is CPU-only; CUDA acceleration is not included in this installer.

## Optional video tools

Video processing uses FFmpeg and FFprobe from the application-managed per-user tools directory, not the system `PATH`. The first video job checks for valid stored executables and offers setup if they are missing or invalid. Downloads are restricted to the pinned Gyan.dev archive over HTTPS, checked against its pinned SHA-256, safely limited to the expected executable entries, and smoke-tested before being committed. Failed setup presents a retry/cancel choice; canceling setup does not affect image inference. Gyan.dev's Essentials build is GPLv3; its source and licensing terms are documented at [Gyan.dev FFmpeg builds](https://www.gyan.dev/ffmpeg/builds/).

## Icon and signing

The Electron/NSIS Windows target uses `frontend/build/icon.ico`, generated from the checked-in `frontend/build/icon.svg` source. The application does not currently have a signing identity configured. The installer, Electron executable, and Python worker are unsigned. Unsigned downloads can trigger a strong SmartScreen warning and some enterprise policies may block them; signing improves publisher identification, but a new signed release can still receive a SmartScreen warning until reputation builds. Public distribution needs an organization-controlled Authenticode certificate or an eligible signing service, secure private-key handling, SHA-256 signing with an RFC 3161 timestamp, and post-build signature verification for the installer and shipped executables. Certificate/service provisioning and credentials are external release dependencies; none are stored in this repository.

References: [Microsoft SmartScreen reputation guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation), [Microsoft code-signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options), and [SignTool timestamping](https://learn.microsoft.com/en-us/windows/win32/seccrypto/time-stamping-authenticode-signatures).

## Release blockers

- The model assets and registry are published, but hosted installation and real model inference from a packaged app still require end-to-end verification.
- The application update feed is a separate GitHub Releases channel; no application release/update feed has been published or tested. See [application updates](APP_UPDATES.md).
- Video processing requires a successful user-approved FFmpeg/FFprobe setup; absence of those tools does not affect image inference or application startup.
- A signing certificate and signed, timestamped artifacts are required for a trusted publisher release.
- Real-media validation and clean-Windows packaged inference remain to be completed.
