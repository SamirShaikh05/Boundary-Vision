# Windows release requirements

> **Release status:** The current installer is not ready for public distribution. The FFmpeg corresponding-source and third-party materials have not been completed and reviewed, distributed binaries are unsigned, no hosted model assets or live application update feed are configured, and clean-machine end-to-end validation remains outstanding.

## Packaged runtime

The Windows installer contains a PyInstaller one-folder worker with its own Python runtime and CPU PyTorch, Ultralytics, OpenCV, and worker code. This build used Python 3.15.2, PyTorch 2.14.1+cpu, Ultralytics 8.4.190, OpenCV 5.0.0.93, and PyInstaller 6.22.3. The release script now requires the exact Python version in `.python-version` and installs the version-pinned Windows release environment in `backend/requirements-release.txt`; this lock was captured from the successfully packaged environment and should be deliberately refreshed only after validation. It pins versions, not wheel hashes, so a controlled package index and retained build artifacts are still needed for stronger supply-chain reproducibility. The developer setup remains unpinned. Electron launches the packaged executable from `process.resourcesPath`; it does not need the build machine's activated venv, working directory, or Python installation. FFmpeg and FFprobe are copied as matched executables under Electron resources and resolved from `process.resourcesPath`. Models are not bundled. Versioned checkpoints live under `userData/models/{model-id}/{model-version}/{filename}`; settings including the selected model version remain under `userData` across application updates.

This packaging approach was inspected and the worker capability handshake was exercised from the final unpacked layout on the build machine. Full inference from the installed layout and a clean-machine test remain outstanding. This build host supplied Gyan's Windows x64 FFmpeg 9.0.2 `full_build`; the script now requires the matching upstream `LICENSE` and `README.txt`, and bundles both with the executables. It does not pin or fetch an FFmpeg build, so record and review the selected version/build provenance for each release. The PyInstaller log reports missing `lap`, an optional Ultralytics tracking dependency; this product does not use object tracking. The shipped runtime is CPU-only; CUDA acceleration is not included in this installer.

## FFmpeg license and source materials

The bundled upstream README identifies this exact binary family as Gyan's `9.0.2-full_build-www.gyan.dev`, states GPL v3, and identifies FFmpeg commit `946fcce07b`. Running the staged executable confirms `--enable-gpl`, `--enable-version3`, and GPL version 3-or-later output from `ffmpeg -L`; the configuration includes `libx264` and `libx265` (among many other external libraries). The video worker specifically uses the `libx264` encoder. The installer includes the exact upstream GPLv3 license text and README with build configuration/provenance. The package script now rejects a different FFmpeg profile or one without `libx264`, so changing binaries requires an explicit license/provenance review and updates to this guard.

The FFmpeg process is launched as a separate executable rather than linked into the Electron or Python process. This inventory does not determine the licensing effect on the rest of Boundary Vision; distribution of the FFmpeg executables themselves still carries their license obligations. FFmpeg's official guidance says enabling GPL components makes FFmpeg GPL, and GPLv3 object-code conveyance requires access to corresponding source. For this static full build, the release source package must match the actual build and cover FFmpeg plus the enabled external libraries, patches, build configuration/scripts, and necessary build/install instructions; an upstream FFmpeg source commit alone is not enough to establish that the Gyan binary is reproducible.

Before public redistribution, publish and retain the complete corresponding source package matching the bundled FFmpeg binary and build configuration/scripts; include notices and convenient source access with the installer/release. Verify applicable third-party library notices and terms for this full build. The FFmpeg upstream source commit is identified in `resources/ffmpeg/UPSTREAM-README.txt`; this repository does not yet contain or host the complete matching Gyan build source/toolchain package. `package-windows.ps1 -Publish` now refuses to proceed unless `BOUNDARY_VISION_FFMPEG_SOURCE_ARCHIVE` points to a reviewed source bundle file. The script only checks that the file exists: release owners must inspect it and upload it to the draft release before publishing. Release/legal review is still required; this document is an engineering inventory, not legal advice.

References: [FFmpeg licensing guidance](https://ffmpeg.org/legal.html), [FFmpeg source downloads](https://ffmpeg.org/download.html), [GNU GPL version 3](https://www.gnu.org/licenses/gpl-3.0.en.html), and the [Gyan FFmpeg build project](https://github.com/GyanD/codexffmpeg).

## Icon and signing

The Electron/NSIS Windows target uses `frontend/build/icon.ico`, generated from the checked-in `frontend/build/icon.svg` source. The application does not currently have a signing identity configured. The installer, Electron executable, Python worker, and FFmpeg executables are unsigned. Unsigned downloads can trigger a strong SmartScreen warning and some enterprise policies may block them; signing improves publisher identification, but a new signed release can still receive a SmartScreen warning until reputation builds. Public distribution needs an organization-controlled Authenticode certificate or an eligible signing service, secure private-key handling, SHA-256 signing with an RFC 3161 timestamp, and post-build signature verification for the installer and shipped executables. Certificate/service provisioning and credentials are external release dependencies; none are stored in this repository.

References: [Microsoft SmartScreen reputation guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation), [Microsoft code-signing options](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options), and [SignTool timestamping](https://learn.microsoft.com/en-us/windows/win32/seccrypto/time-stamping-authenticode-signatures).

## Release blockers

- Real HTTPS hosting and independently verified uploaded checkpoints are required for optional model installation in shipped builds.
- The complete corresponding-source archive and third-party license review/materials for this GPL-enabled FFmpeg build are required before redistribution. The publish script now gates on an archive path but does not validate its contents or attach it automatically.
- A signing certificate and signed, timestamped artifacts are required for a trusted publisher release.
- Real-media validation and clean-Windows packaged inference remain to be completed.
